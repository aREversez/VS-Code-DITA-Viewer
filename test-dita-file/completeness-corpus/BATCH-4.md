## 这批的根本问题：class 是 DTD 的默认值

DITA 1.x 里 `@class` 通常不写在文件里，而是 DTD 的默认值。语料的文件都有 DOCTYPE，所以 Oxygen 看得到每个元素的 class；
扩展读的是原始 XML，看不到。**要靠一张"元素名 → class"的表补上。** 仓库里已经有：

- `scripts/dita-class-extracted.json`：从 DITA-OT 的 DTD（base、technicalContent、bookmap）提取的完整表，228 个 topic 元素、
  35 个 map 元素，带 `classValue`（完整的 class 链）和来源文件与行号。生成脚本是 `scripts/extract-dita-class.cjs`。
- `src/parser/standardTagMap.ts` 与 `mapTagMap.ts`：手工维护的"元素 → 基类型"（只有第一对）。

会话要先回答：**这张表怎么进入扩展运行时**（现在它只是脚本的产物）：是生成一个模块并在构建时更新，还是别的办法；
表之外的元素（自定义特化）没有 class，相关检查对它们要跳过并写进账本，不要猜。

### 回答：class 表怎么进入运行时

**结论：由现有提取脚本再生成一个 `src/` 内的 TS 模块，随扩展打包；JSON 继续留作出处证据。**

1. **为什么不能运行时读 JSON。** `tsconfig.json` 是 `rootDir: src` + `include: src/**/*`，`scripts/` 不在编译范围；把 JSON 复制进 `src/`
   就是第二份真相。esbuild 会把 import 的 JSON 内联，但这 66 KB 里大半是出处（`sourceFile`/`sourceLine`/`generatedAt`），
   对运行时无用，而且每次重新提取都会改 `generatedAt`，造成无意义的 diff。
2. **生成什么。** `src/parser/ditaClassDefaults.ts`，导出两个 `Record<string, string>`（`tagName → classValue`），按字母排序，
   文件头写「generated by scripts/extract-dita-class.cjs from the DITA-OT 1.3 DTDs; do not edit」。263 条、约 11 KB 源码，
   minify 后进 bundle 约 6 KB（当前 `dist/extension.js` 是 557 KB）。
3. **谁生成、怎么防漂移。** `extract-dita-class.cjs` 增加 `--emit-module`（与 JSON 同一次提取写出）与 `--check-module`（只比较、
   不写），后者接进 `npm run verify`（`check:class-table`）：DTD 或脚本变了而模块没重新生成，门禁就拦住。拿不到本机 DITA-OT 时
   `--check-module` 降级为「已提交的 JSON 对模块」比较，仍能拦住手改。
4. **运行时语义。**
   - `classOf(node)`：`@class` 存在就用作者写的，否则查表；表里没有 = 表外元素，**所有依赖 class 的检查跳过它**，账本写明。
   - 只提取了 DITA-OT 的 `base` / `technicalContent` / `bookmap`，与语料 5 的 DOCTYPE（`topic.dtd` / `map.dtd`）一致；其它 doctype
     的文件整体跳过，不猜。
   - 表给的是完整 class 链，所以「是否泛化/特化」只看两条链本身（后者是前者的前缀且更长），不需要第二张表。
5. **不动的地方。** `standardTagMap.ts` / `mapTagMap.ts` 继续服务渲染（元素 → 基类型），本表不替代它们，避免改渲染层；两者可能不一致
   的地方用一条测试钉住（本表每个条目都必须是那两个手动映射的子集关系），发现偏差交给后续统一。
6. **没采纳的备选：** 把 JSON 放 `media/` 运行时读 —— 要处理 vsix 分发、读文件与 tree-shaking，版本漂移更难发现。

## 需要先做的决定：DTD 校验（`MSG_*` 三个）

这三个是 DTD 校验器的结果，不是 `dmv.*` 的检查。要报出和 Oxygen 一样的结果，需要对元素名、属性、内容模型做校验。
会话先把选项和代价写清楚，再由维护者决定：

1. **只做元素与属性是否声明**：元素名可以用上面那张表判断；属性则需要每个元素的属性清单，现有提取脚本没有，要扩展。
   内容模型（"不允许出现在这里"）做不了。
2. **接入一个 DTD 校验器**：要评估一个能在扩展里运行的实现（原生模块、WASM）、DITA DTD 的随包分发条件（OASIS 许可）、体积与
   构建影响。代价最大。
3. **接受差异**：三个 `MSG_*` 记为有理由的 n/a，写明扩展不做 schema 校验。

**这三个选项里，先不要实现任何一个**，先把评估写出来，等维护者定。其余 11 个 id 不依赖这个决定。

### 评估（已写，待拍板）

共同事实：解析层是 sax（非校验）+ 自写实体预处理，DOCTYPE 只被跳过，所以既没有元素/属性声明，也没有 DTD 默认值——这正是要 class
表的原因。三个 `MSG_*` 是 DTD 校验器的产物，语料 1 里出现它们的 `invalid.dita` 同时也触发别的 id。

| 选项 | 能做到什么 | 要付的代价 | 风险 |
| --- | --- | --- | --- |
| 1 元素与属性声明 | 未声明元素（class 表已有 228 topic + 35 map 个声明元素）、未声明属性（需扩展提取器读同一批 `.mod` 里的 `ATTLIST`，含通用属性合并规则）；内容模型做不了 | 提取器扩展约 1 个工作日；1 个新类别 + 2 条规则 + 账本 + 探针；属性表估计 40–60 KB 源码，零运行时依赖 | 表外 doctype（learning 等）必须整体跳过，否则误报；特化元素漏在表外也会误报 |
| 2 接入 DTD 校验器 | 包含内容模型，理论最接近 Oxygen | 候选 `xmllint-wasm`（libxml2 编到 WASM，wasm+js 约 860 KB，Node ≥ 16，内部用 worker thread）：需核实包装层是否暴露 DTD 校验（其文档以 XSD 为主，DTD 要对上 xmllint 的 `--valid`）、1.7 MB / 168 个文件的 DTD 目录怎么让校验器看见（不能依赖本机 DITA-OT）；DTD 是 OASIS 发布物、DITA-OT 以 Apache-2.0 分发，随包要附声明；每文件一次 worker 有启动开销，得缓存或批处理 | 体积 +1.7 MB（未压缩）、分发许可、跨平台；`xmllint` 只给文本消息，要对上三个 `MSG_*` 还得按文本匹配，仍不等于 Oxygen 的措辞与 scope |
| 3 接受差异 | 无 | 0：3 行写成有理由的 n/a，parity 继续把这 3 行留在 Oxygen-only 并记录 | `invalid.class.format` 的「未声明元素」形态在使用中会漏——但本批的 class 检查只管「有 class 的元素是否被按 DITA 解析」，元素是否存在不归它 |

### 决定：选 3，并把「不做 schema 校验」写实

维护者已定：**接受差异**。代价对比见上表；两项落地要求：

- 三个 `MSG_*` 与 Xerces 的「没有关联 schema/DTD」文本进 `ACCEPTED_PROBLEM_IDS` /
  `ACCEPTED_DESCRIPTIONS`（`src/test/editor/oxygenReport.ts`），`scripts/oxygen-diff.cjs` 把它们列成
  "accepted differences (not counted)"，既不计入 diff，也不再用退出码 1 报「未映射 id」。
- `OXYGEN-PROBLEMS.md` 写明范围：不覆盖元素/属性是否声明和内容模型；以后若要补，从选项 1 开始，
  并且只对已知的标准 DOCTYPE 生效。日常的 schema 校验交给 VS Code 里支持 DTD/目录的 XML 语言服务器。

`dmv.invalid.DITA.reference` / `dmv.invalid.DITA.uri.target` 不记为 gap：五份报告都没有这个 id
（探针拿到的是 `dmv.ref.res.as.dita` 与 `dmv.invalid.parse.dita.content`），账本记为 n/a 并写明观察。

## 探针设计的特别注意

- **一条规则一个文件**（同前几批）。
- **注意"一个文件同时触发几条"**：被按 DITA 解析的非 DITA 文件既有 class 问题也有解析问题。探针要让每条规则的正例**只**触发它自己，
  或在 README 的表里写明每个文件期望出现什么，不要把一条规则的结果算到另一条头上。
- **DOCTYPE 保留**，只有明确要问"没有 DOCTYPE 时"的探针才去掉，并在注释里写明。
- 控制：沿用 `control-missing.dita`；每组再配一个 Oxygen 一定会报的对照，使沉默有意义。
